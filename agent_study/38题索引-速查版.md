## A. Agent 项目与整体架构（Q1-Q4）

### Q1 自我介绍 + Agent 项目经历
- 主文档：Day7 §2、§5
- 一句话方向：用「问题定义→架构→难点→方案→结果」讲项目主线，不流水账。
- travel map 抓手：多约束旅行规划 + 校验修复闭环 + 可量化提升。

### Q2 Agent 项目核心架构
- 主文档：Day1 §2（八层架构）、Day4 §6（状态机）
- 一句话方向：目标→规划→记忆→工具→执行→校验→修复→评估八层。
- travel map 抓手：工具层接地图事实，校验层判天数/地理/闭环。

### Q3 为什么用 LangGraph / 是否过度设计
- 主文档：Day1 §5 Q3、Day4 §6
- 一句话方向：任务是多步+多工具+可执行，需要显式状态与可控流转；复杂度由任务决定。
- travel map 抓手：`plan→verify→repair→finalize` 必须显式建模，否则无法定义终止与重试。

### Q4 为什么不直接用 Claude Code / 内部 Agent
- 主文档：Day1 §5 Q2
- 一句话方向：通用 Agent 覆盖广但难满足领域 schema、可解释校验与回归评测。
- travel map 抓手：需要结构化 `dailyPlans/validation` 与可判定约束。

## B. Skill、MCP 与工具链（Q5-Q8）

### Q5 Skill 机制做什么
- 主文档：Day3 §1、§2
- 一句话方向：把可复用能力封装成可发现、可验证、可调用的模块。
- travel map 抓手：把 geocode/route 封装为标准工具能力。

### Q6 你在 Skill 上做了什么 / 里面放代码吗
- 主文档：Day3 §3（schema 模板）
- 一句话方向：Skill 应放「能力封装 + 参数校验 + 错误处理」，代码化但要接口化。
- travel map 抓手：工具入口做参数补全、返回校验、错误码标准化。

### Q7 MCP vs Skill vs CLI 区别
- 主文档：Day3 §1、§2
- 一句话方向：MCP 是协议/接入层，Skill 是能力封装层，CLI 是执行入口；层次不同。
- travel map 抓手：地图能力可经 MCP 接入、以 Skill 复用、由后端流程调用。

### Q8 工具链能否 Skill 化
- 主文档：Day3 §2、§7
- 一句话方向：可以，前提是标准化 schema + 幂等 + 缓存 + 错误恢复。
- travel map 抓手：`geocode_key/route_key` 幂等键 + 缓存去重。

## C. Agent 循环与任务范式（Q9-Q11）

### Q9 Agent 循环流程（ReAct）
- 主文档：Day1 §3.1、Day3 §4
- 一句话方向：Thought→Act→Observation 循环直至完成。
- travel map 抓手：想是否可行→调地图→看路程→判断→重排。

### Q10 Plan&Execute vs ReAct
- 主文档：Day1 §3
- 一句话方向：Plan&Execute 结构可控，ReAct 灵活应变；复杂约束用前者，探索用后者。
- travel map 抓手：主流程 Plan&Execute + 修复阶段局部 ReAct。

### Q11 死循环怎么解决
- 主文档：Day4 §5（三道防线）
- 一句话方向：轮次上限 + 改善阈值 + 同动作去重，无增益则 fallback。
- travel map 抓手：修复轮次上限 + issue 严重度不降则停。

## D. 上下文工程（Q12-Q16）

### Q12 上下文如何分层组装
- 主文档：Day2 §2（五层）、§3（装配原则）
- 一句话方向：System/Task/Memory/ToolResults/Conversation 五层 + 优先级预算。
- travel map 抓手：硬约束与工具证据优先，对话最后压缩。

### Q13 上下文是不是 System+Memory+Tools+Conversation
- 主文档：Day2 §2、§7 Q1
- 一句话方向：不够，要补 Task 层（硬约束）；否则约束丢失。
- travel map 抓手：`totalDays/必回酒店` 属 Task 层，必须独立保真。

### Q14 上下文超长怎么办 / 压缩
- 主文档：Day2 §4（保真压缩）、§7 Q2
- 一句话方向：分层预算 + 优先级裁剪，保留状态快照/约束台账/证据摘要/决策依据。
- travel map 抓手：先压对话，绝不压约束与工具证据。

### Q15 压缩丢工具历史致重复调用
- 主文档：Day2 §4.3、§7 Q3；Day3 §7
- 一句话方向：保留工具证据索引（成功/失败计数 + 最后结果/错误），非全文日志。
- travel map 抓手：每地点维护 `success/fail_count + last_result`。

### Q16 长期运行上下文膨胀
- 主文档：Day2 §4、Day6 §4（治理）
- 一句话方向：滚动摘要 + 状态快照 + 过期淘汰 + 证据索引化。
- travel map 抓手：仅保留最近轮 + 关键约束 + 当前最佳方案引用。

## F. RAG 项目与检索链路（Q20-Q27）

### Q26 文档隔离 / 关联关系 / 术语文档

- 一句话方向：按域隔离命名空间 + 术语表单独维护 + 关联通过元数据关联。

### Q27 Code-RAG 怎么设计
- 主文档：Day5 §2（迁移到代码域）
