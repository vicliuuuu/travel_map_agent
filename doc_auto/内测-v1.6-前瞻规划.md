# 内测 v1.6 前瞻规划：记忆层 + 局部重算

> 创建日期：2026-08-06
> 状态：**仅规划，尚未开发**
> 基线版本：[`内测-v1.5-前瞻规划.md`](./内测-v1.5-前瞻规划.md)
> 终态参照：[`map-travel-agent-终极构想.md`](./map-travel-agent-终极构想.md)

本版本补齐两块个性化与体验能力：**长期记忆**（学习并复用用户偏好）与**局部重算**（改一个点只重算受影响部分，不推翻全局）。对应理想图里"记忆层"和"随时可改，局部重算"。

---

## 1. 版本定位

| 维度 | v1.5（前置） | v1.6（本版本） |
|------|-------------|----------------|
| 记忆能力 | 无长期记忆 | 跨会话沉淀并注入用户偏好 |
| 修改成本 | 改动一个点触发全局重规划 | 只重算受影响的日/段 |
| 输入完整度 | 单酒店锚点 | 支持多酒店/换酒店 |

一句话目标：**让 Agent 记住"你是谁、你喜欢什么"，并且在你临时改点时只动受影响的局部。**

---

## 2. 前瞻规划

### 2.1 P0（必须）

1. **长期记忆存储与注入**
   - 记忆项：节奏偏好（快/慢）、交通偏好（地铁/步行/驾车）、兴趣标签（博物馆/自然/美食）、硬性禁忌（不早起、少走路）、"少换酒店"等模式；
   - 存储：用户维度键值（内测可本地文件/轻量库），支持读写与失效；
   - 注入时机：`build_context` 阶段（v1.3 状态机）注入偏好，影响策略默认值与打分权重。

2. **局部重算（Incremental Replan）**
   - 变更事件建模：`add_place / remove_place / move_place / change_day`；
   - 影响域分析：仅重算受影响的日与相邻段，其余日程与已确认结果保持不变；
   - 局部重算后仍走 v1.3 的 verify/repair，但作用域收敛到受影响范围。

3. **记忆写入冲突治理**
   - 偏好冲突（本次行为与历史偏好矛盾）时的合并策略：本次显式操作优先，历史偏好作为默认建议；
   - 记忆写入必须记录来源与时间，可回溯、可撤销。

### 2.2 P1（应做）

1. **多酒店 / 换酒店支持**
   - 输入层支持多个酒店锚点及其生效日期区间；
   - 每日闭环按当日生效酒店计算首尾腿。

2. **偏好可解释注入**
   - 输出中说明"因为你偏好少走路，本次采用了 least_transfer 策略"，让记忆影响可见。

### 2.3 P2（可选）

1. **偏好自动学习**
   - 从用户历次删/留景点、调整行为中自动归纳偏好候选（需用户确认后固化，避免误学）。

## 3. 关键方案设计

### 3.1 记忆数据结构（示例）

```json
{
  "userId": "u_123",
  "preferences": {
    "pace": "slow",
    "transport": ["metro", "walk"],
    "interests": ["museum", "food"],
    "taboos": ["early_start"],
    "hotelSwitchAversion": true
  },
  "meta": { "updatedAt": 0, "source": "explicit|learned", "revisable": true }
}
```

### 3.2 局部重算流程

```
onChange(event):
    affected = analyze_impact(event, currentPlan)   # 受影响的日/段
    subPlan = replan(affected, context)             # 仅重算受影响域
    merged = merge(currentPlan, subPlan)
    verify(merged, scope=affected)                  # 局部校验
    if fail: repair(scope=affected)                 # 局部修复
    return merged
```

- 未受影响的日/段直接复用，节省调用与保持稳定；
- 局部重算与全量重算共用同一状态机，仅作用域不同。

## 4. 埋点设计（在 v1.3–v1.5 trace 基线上扩展）

### 4.1 新增事件与字段

| 事件点 | eventType | 新增 payload | 用途 |
|--------|-----------|--------------|------|
| 记忆读取 | `memory_read` | `userId`、`hit`、`prefKeys` | 记忆命中率 |
| 记忆写入 | `memory_write` | `source(explicit/learned)`、`conflictResolved` | 写入与冲突治理审计 |
| 偏好注入 | `preference_inject` | `injectedPrefs`、`affectedStrategy/weights` | 记忆对决策的影响 |
| 局部重算 | `incremental_replan` | `changeType`、`affectedScope`、`reusedRatio` | 局部重算范围与复用率 |

### 4.2 埋点要求

- 记忆读写全部可追溯来源与时间；
- 局部重算需记录"复用比例"（未重算部分占比），用于验证增量效果；
- 记忆冲突处理必须埋点，不静默覆盖。

## 5. 评价指标（验收标准）

### 5.1 功能性指标

| 指标 | 定义 | 目标值 |
|------|------|--------|
| 偏好注入生效率 | 存在历史偏好时最终方案体现该偏好的比例 | ≥ 90% |
| 局部重算正确率 | 变更后未受影响日程保持不变的比例 | 100% |
| 局部重算收敛率 | 局部重算后校验通过的比例 | ≥ 85% |
| 多酒店闭环正确率 | 多酒店样例每日按当日酒店正确闭环的比例 | 100% |

### 5.2 效率指标（相对全量重算对比）

| 指标 | 定义 | 目标值 |
|------|------|--------|
| 局部重算复用率 | 变更时未重算部分占比 | ≥ 60% |
| 局部重算耗时 | 相比全量重算的耗时下降 | 下降 ≥ 40% |
| 局部重算工具调用数 | 相比全量重算下降 | 下降 ≥ 40% |

### 5.3 可靠性指标

| 指标 | 定义 | 目标值 |
|------|------|--------|
| 记忆冲突正确处理率 | 偏好冲突按"显式优先"正确合并的比例 | 100% |
| 记忆可撤销率 | 写入的记忆均可回溯/撤销 | 100% |

### 5.4 验收结论判定

- **通过**：5.1 全达标，5.2 至少 2/3 达标，5.3 全达标，回归样例通过；
- **不通过**：局部重算正确率（未受影响不变）或多酒店闭环不达标必须回炉。

## 7. 风险与边界

1. 记忆隐私与合规：用户偏好属敏感数据，需可删除、可导出；
2. 自动学习易误学，P2 必须"确认后固化"；
3. 局部重算影响域分析若不准，可能出现"局部改但全局失配"，需校验兜底；
4. 多酒店逻辑复杂化按日闭环，需重点回归。

---

## 8. 关键任务拆解（难点分解）

> 本版本最硬的是"局部重算影响域分析"（判错就会全局失配）与"多酒店按日闭环"。

### 8.1 难点：局部重算影响域分析（本版本最硬）

**子步骤**
1. 建立依赖图：把行程建模为"日 → 段 → 点"，记录每个点所在日、前驱/后继点、所依赖的酒店腿。
2. 变更影响传播规则：
   - `remove_place`：影响所在日 + 该点前后段的重连；
   - `add_place`：影响插入目标日（可能触发该日超载 → 连锁到相邻日）；
   - `move_place`：影响源日与目标日两处；
   - `change_day`：影响涉及的相邻日。
3. 计算 `affectedScope`（最小受影响日集合），冻结其余日的结果。
4. 只对 affectedScope 重跑 plan/verify/repair，再 merge 回全局。
5. 一致性兜底：merge 后做一次"跨日边界"轻校验（酒店腿、跨城衔接），防止局部改动破坏边界。

**关键实现点**：影响传播必须"宁可多算一日也不能漏"——漏算会导致全局失配；`reusedRatio` 要真实统计未重算部分，作为增量效果证据。

**完成判据**：未受影响日程保持不变 100%；复用率 ≥ 60%；耗时/调用较全量下降 ≥ 40%。

### 8.2 难点：多酒店按日闭环

**子步骤**
1. 输入建模：每个酒店锚点带 `effectiveDays`（生效日区间/夜次），构建"日 → 当日酒店"映射。
2. 每日闭环按当日酒店生成首尾腿（首段 `hotel_d → first`，末段 `last → hotel_d`）。
3. 换酒店日处理：定义换酒店当天的行李转移腿（旧酒店 → 新酒店），并计入当日时间预算。
4. 与 v1.5 往返成本校验联动：换酒店日往返成本单独评估。

**关键实现点**：换酒店当天是最易出错的边界（既要退房又要入住又要游览），需专门样例；无当日酒店映射时回退为"无酒店闭环"逻辑。

**完成判据**：多酒店样例每日按当日酒店正确闭环 100%，换酒店日不丢行李转移腿。

### 8.3 难点：记忆写入冲突治理

**子步骤**
1. 定义冲突：本次显式操作与历史偏好矛盾（如历史"少走路"，本次主动加了远距徒步点）。
2. 合并策略：本次显式操作生效于本次；是否更新长期偏好需"确认后固化"（P2 自动学习同理）。
3. 写入审计：记录 `source(explicit/learned)`、`updatedAt`、可撤销标记。
4. 提供撤销/导出接口（隐私合规）。

**完成判据**：冲突按"显式优先"正确处理 100%；记忆可撤销/可导出。

## 9. 建议实施顺序（本版本内）

1. 先做 8.1 局部重算（体验与效率核心，且复用 v1.3 状态机的作用域参数）；
2. 再做 8.2 多酒店闭环（输入层补齐）；
3. 最后做记忆存储 + 8.3 冲突治理 + 偏好注入（与 v1.4 权重/策略默认值对接）。
