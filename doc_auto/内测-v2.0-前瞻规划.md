# 内测 v2.0 前瞻规划：对话式旅行顾问 + 终态整合验收

> 创建日期：2026-08-06
> 状态：**仅规划，尚未开发**
> 基线版本：[`内测-v1.7-前瞻规划.md`](./内测-v1.7-前瞻规划.md)
> 终态参照：[`map-travel-agent-终极构想.md`](./map-travel-agent-终极构想.md)

本版本是**终态里程碑**：在 v1.3–v1.7 打牢的状态机、策略、工具/校验、记忆/局部重算、可观测基础上，补齐"先理解再规划、多轮自然语言对话"的体验层，并对整个理想形态做整合验收。

> 前置约束：底层能力（校验/修复/记忆/策略/可观测）不齐时，对话只会放大幻觉。因此本版本放在最后，且以"整合与验收"为核心，而非新增底层能力。

---

## 1. 版本定位

| 维度 | v1.7（前置） | v2.0（本版本） |
|------|-------------|----------------|
| 交互形态 | 表单式一次性提交 | 多轮自然语言对话，先理解后规划 |
| 澄清能力 | 无 | 主动澄清硬约束（预算/节奏/带娃/禁忌） |
| 输出 | 结构化路书 | 对话 + 结构化路书 + 每步地图证据 |
| 系统整体 | 各能力已就绪 | 整合为一个可对话的旅行副驾驶并终态验收 |

一句话目标：**让用户像和真人旅行顾问对话一样使用，但每一步都有地图证据、可校验、可修复、可复盘。**

---

## 2. 前瞻规划

### 2.1 P0（必须）

1. **多轮对话编排**
   - 对话状态与规划状态机（v1.3）打通：对话轮次驱动 `collect → build → plan → verify → repair → finalize`；
   - 支持"先理解后规划"：在信息不足时先澄清，不急于出路线（对应理想图"先理解解束"）。

2. **主动澄清与约束抽取**
   - 从自然语言抽取硬约束（时间/预算/节奏/带娃/老人/禁忌）并结构化；
   - 关键信息缺失时主动追问（澄清问题数受控，避免打断体验）。

3. **对话内局部修改**
   - 用户在对话中说"第二天太累了/去掉某个点/换个酒店"，触发 v1.6 局部重算，只改受影响部分并回话解释。

4. **每步地图证据绑定**
   - 每个关键结论（顺序、时长、跨城）在对话中附地图/工具证据引用，保证"可对话但不失真"。

### 2.2 P1（应做）

1. **解释性对话**
   - 用户追问"为什么这么排"时，基于 v1.4 打分与 v1.7 trace 给出可解释回答。

2. **多方案对话推荐**
   - 主动给 A/B/C 方案（省时/少走路/亲子）并说明触发条件与代价。

### 2.3 P2（可选）

1. **语音/多模态入口**（远期，视需求）。

## 3. 关键方案设计

### 3.1 对话-规划双状态机

```
DialogState: greet → gather → clarify → confirm → present → refine
                                   │                          │
                                   └──> PlanStateMachine(v1.3) <┘
```

- 对话状态管理"和用户聊到哪"，规划状态机管理"任务算到哪"；
- `refine` 阶段的局部修改走 v1.6 增量重算，避免全局重来。

### 3.2 约束抽取与澄清策略

- 抽取器输出结构化约束集合 + 置信度；
- 低置信/缺失的硬约束才追问，其余用记忆（v1.6）或合理默认补齐；
- 澄清问题总数设上限，避免"审问式"体验。

---

## 4. 埋点设计（在 v1.3–v1.7 基线上扩展对话维度）

### 4.1 新增事件与字段

| 事件点 | eventType | 新增 payload | 用途 |
|--------|-----------|--------------|------|
| 对话轮次 | `dialog_turn` | `turnIndex`、`dialogState`、`intent` | 对话流转与轮次分析 |
| 约束抽取 | `constraint_extract` | `extracted{}`、`confidence`、`missing[]` | 抽取准确率 |
| 主动澄清 | `clarify` | `question`、`triggeredBy` | 澄清频率与必要性 |
| 对话内修改 | `dialog_refine` | `changeType`、`incrementalReused` | 对话修改与局部重算联动 |
| 证据引用 | `evidence_ref` | `claim`、`sourceEvent` | 结论-证据可追溯 |

### 4.2 埋点要求

- 每个对话结论必须能追溯到底层工具/校验证据事件；
- 澄清与抽取全程可回放，纳入 v1.7 复盘；
- 对话维度指标与 v1.7 指标体系统一存储。

## 5. 评价指标（验收标准）

### 5.1 对话质量指标

| 指标 | 定义 | 目标值 |
|------|------|--------|
| 约束抽取准确率 | 正确抽取用户硬约束的比例 | ≥ 90% |
| 必要澄清率 | 澄清确为信息缺失所需（非冗余追问）的比例 | ≥ 85% |
| 过度澄清率 | 单次对话澄清问题数超上限的比例 | ≤ 5% |
| 证据绑定率 | 关键结论均有可追溯证据引用的比例 | 100% |

### 5.2 对话内修改指标

| 指标 | 定义 | 目标值 |
|------|------|--------|
| 局部修改正确率 | 对话修改仅影响相关部分的比例 | 100% |
| 修改响应复用率 | 对话修改复用 v1.6 增量重算的比例 | ≥ 80% |

### 5.3 终态整合验收（Definition of Done，对齐终极构想 §7）

| 维度 | 标准 | 目标 |
|------|------|------|
| 功能性 | 复杂多城输入稳定产出可执行计划 | 达标 |
| 正确性 | 校验结论与最终日程一致、冲突可追踪 | 达标 |
| 自主性 | 发现不可行能自动修复，不需人工重提 | 达标 |
| 可解释性 | 每个关键调整均有明确理由 | 达标 |
| 可维护性 | 输出 schema 稳定、核心闭环测试覆盖 | 达标 |
| 可靠性 | 失败可回退、每轮有日志、可复盘 | 达标 |

### 5.4 验收结论判定

- **通过（判定为达到理想终态）**：5.1、5.2 全达标，且 5.3 六个维度全部达标，v1.7 评测集门禁通过；
- **不通过**：任一终态维度未达标，继续在对应能力版本回炉，而非在对话层打补丁。

## 7. 风险与边界

1. 对话自由度提高会放大幻觉，必须强绑定底层证据与校验；
2. 澄清体验是双刃剑，追问过多反而变差，需严格控上限；
3. 终态验收依赖 v1.3–v1.7 全部达标，任一前置薄弱都会在此暴露；
4. 多模态为远期可选，不纳入终态硬性验收。

---

## 8. 关键任务拆解（难点分解）

> 本版本最硬的是"约束抽取 + 主动澄清"（自然语言 → 结构化，且要克制追问）与"对话-规划双状态机"。

### 8.1 难点：约束抽取 + 主动澄清（体验成败关键）

**子步骤**
1. 定义硬约束 schema：时间/天数、预算、节奏、同行人（带娃/老人）、交通偏好、禁忌。
2. 抽取器：从自然语言抽取上述字段，输出值 + 置信度 + `missing[]`；结合 v1.6 记忆填充默认值。
3. 澄清决策：仅当"硬约束缺失且无记忆默认可补"时才追问；对置信度低的抽取值可做确认式追问。
4. 澄清预算：单次对话澄清问题数设上限，超限则用默认值继续并说明假设。
5. 确认阶段：进入规划前给用户一次结构化确认（"我理解你要 X，对吗"）。

**关键实现点**：抽取尽量走结构化 function-calling 而非自由文本解析；"该问 vs 不该问"的边界要用样例校准，过度澄清是最大体验杀手。

**完成判据**：约束抽取准确率 ≥ 90%，过度澄清率 ≤ 5%，必要澄清率 ≥ 85%。

### 8.2 难点：对话-规划双状态机打通

**子步骤**
1. 定义对话状态 `greet/gather/clarify/confirm/present/refine` 与转移条件。
2. 在 `confirm → present` 处触发 v1.3 规划状态机（一次完整 plan）。
3. `refine` 处的用户修改映射为 v1.6 变更事件，触发局部重算，仅回话受影响部分。
4. 双状态机上下文隔离但共享同一 requestId/traceId，保证可复盘。

**关键实现点**：对话状态管"聊到哪"，规划状态机管"算到哪"，二者边界要清晰，避免把规划逻辑塞进对话层。

**完成判据**：多轮修改场景下对话与规划状态一致，无状态错乱。

### 8.3 难点：每步结论的证据绑定（防对话放大幻觉）

**子步骤**
1. 规划产出的每个关键结论（顺序/时长/跨城/闭馆）关联其来源 trace 事件 id。
2. 对话生成回答时，只允许引用有证据的结论；无证据的表述标注为"建议/待核实"。
3. 用户追问"为什么"时，回溯证据事件（v1.4 打分 + v1.5 工具结果）生成解释。

**关键实现点**：对话自由度越高越要强绑定证据，这是终态"可对话但不失真"的底线。

**完成判据**：证据绑定率 100%。

---

## 9. 建议实施顺序（本版本内）

1. 先做 8.2 双状态机骨架（把 v1.3/v1.6 接进对话流程）；
2. 再做 8.1 约束抽取 + 澄清（体验核心，重点调"该不该问"）；
3. 然后做 8.3 证据绑定 + 解释性对话；
4. 最后做终态整合验收（§5.3 六维度）。
