# 旅行规划 Agent · 内测版本 v1.1.0

锁定日期：2026-08-03  
版本代号：`内测 v1.1.0`  
状态：**已锁定（内测发布）**

> 本文档对应内测 v1.1.0 代码快照。该版本在 v1.0 基线之上完成了输入模型、可行性评估、路书展示与交互体验的系统升级。

---

## 1. 版本定位

内测 v1.1.0 是一个**可本地运行的旅行任务型 Agent 原型**，面向「需要跨城/跨国、多点位、可执行路书」的用户。

| 能力层级 | 是否需要 LLM | 说明 |
|----------|--------------|------|
| 地图标点 | 否 | 按输入顺序在 Google 地图标点，支持酒店 `H` 锚点 |
| 位置解析 | 否 | 展示每个点位的解析地址与经纬度 |
| 智能路书规划 | 是 | Agent 调用 LLM + 地图工具，输出路书、可行性与替代方案 |

**决策层是 Agent + 工具链**：LLM 负责语义规划，Google Maps 提供地理约束，后端本地评估负责可行性兜底与一致性收敛。

## 2. 功能范围（已交付）

### 2.1 输入与交互模型

- 目的地输入为层级结构：国家/地区 -> 城市 -> 点位行；
- 点位行支持类型选择：`景点` / `酒店`（默认 `景点`）；
- 酒店不再单独占用表单，作为“点位类型”统一管理；
- LLM 模型配置仅保留下拉选择，移除手动覆盖输入；
- 页面支持三态布局焦点切换：
  - 输入阶段：参数区居中；
  - 标点阶段：地图居中；
  - 路书阶段：路书居中。

### 2.2 地图能力（Google Maps）

- 支持按点位顺序标记 1、2、3...；
- 若存在酒店点位，地图额外标记 `H`；
- Agent 规划后按推荐顺序绘制路线；
- 标点后展示每个点位的解析地址、坐标、查询串。

### 2.3 Agent 路书能力

后端 `POST /api/agent/plan` / `POST /api/agent/plan/stream` 流程：

1. 预解析点位与酒店地理信息；
2. LLM 工具调用（`geocode_place`、`get_travel_time`）生成候选路书；
3. 后端执行归属校验（错城/错国排除）；
4. 后端执行可行性评估与天数对齐（先自然天数，再对齐用户天数）；
5. 统一输出结构并保证字段一致性（顺序、路书、按日计划、校验结果）。

### 2.4 智能路书展示与导出

右侧路书面板支持展示：

- 行程概述（`summary`）
- 路线策略（`routeStrategy`）
- 住宿摘要（可选）
- 景点速览（`placeSpotlights`）
- 按日行程（`dailyPlans`）
- 行程校验（`validation`）
- 替代方案（`alternativeProposals`）
- 注意事项（`precautions`）

并支持一键导出 `TXT` 路书。

### 2.5 流式进度反馈

- 新增 `POST /api/agent/plan/stream`（NDJSON）；
- 前端显示阶段进度条，覆盖准备、地理解析、LLM 推理、工具调用、校验与输出阶段；
- 规划期间禁用关键按钮，避免重复提交。

## 4. 核心接口

### 4.1 Agent 规划（同步）

- 路径：`POST /api/agent/plan`
- 输入：`destinations`、`totalDays`、`places`、LLM 配置、Google Maps Key
- 输出：`summary`、`recommendedOrder`、`roadbook`、`dailyPlans`、`validation`、`alternativeProposals`、`planData`

### 4.2 Agent 规划（流式）

- 路径：`POST /api/agent/plan/stream`
- 返回格式：`application/x-ndjson`
- 事件类型：
  - `progress`（阶段/百分比/消息）
  - `result`（最终结构化路书）
  - `error`（错误信息）

### 4.3 地图工具（Agent 内部）

| 工具 | 用途 |
|------|------|
| `geocode_place` | 点位名 + 城市 + 国家 -> 经纬度 |
| `get_travel_time` | 两点位间真实驾驶时长与距离 |

## 5. 运行与验证

### 5.1 启动

```bash
node server.js
```

访问：`http://127.0.0.1:8080/index.html`

### 5.2 推荐内测流程

1. 配置 Google Maps Key 并连接地图；
2. 填写国家/城市/点位，按需把某一行类型切换为酒店；
3. 点击「在地图上标点」验证无 LLM 链路；
4. 配置 LLM Key 与模型下拉；
5. 点击「Agent 智能规划」查看流式进度、路书与地图路线；
6. 点击「导出路书 TXT」验证导出内容。

### 5.3 测试

```bash
node --test tests/planner.test.js tests/llm.test.js tests/agent-planner.test.js tests/location-data.test.js
```

内测 v1.1.0 锁定时为 **24/24** 通过。

## 6. 已知限制（内测 v1.1.0）

- 酒店仅支持单锚点；多酒店/换酒店仍未实现；
- 路书时间为范围描述，未与实时公共交通时刻表联动；
- 可行性评估为启发式估算，后续可引入更精细交通模式；
- LLM 事实能力仍依赖模型与提示词，未接入实时网页检索；
- 默认主交通策略偏向驾车估算，跨国轨道交通策略待增强。

## 7. 与 v1.0 对比

| 维度 | 内测 v1.0 | 内测 v1.1.0 |
|------|-----------|-------------|
| 输入模型 | 单城市 + 扁平景点 | 多目的地层级 + 点位类型（景点/酒店） |
| 酒店 | 独立字段，早期含日期耦合 | 点位内统一选择，可选锚点 |
| 可行性 | 弱校验 | 本地归属校验 + 天数对齐 + 替代方案 |
| 输出结构 | 以 `roadbook` 为主 | `roadbook + dailyPlans + validation` |
| 交互反馈 | 单次等待 | 流式阶段进度条 |
| 导出 | 无 | TXT 导出 |
